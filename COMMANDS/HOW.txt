READ-ONLY PREFLIGHT:
  python validate_commands.py
The standalone validator is a convenience preflight, not an authority token and
not a byte-generation lock for a later pull. Each COMMANDS/<id>.txt it checks is
opened once as an ordinary regular file, bounded to 64 KiB, decoded as strict
UTF-8 without BOM, and parsed with LF-only line boundaries. Symlinks,
pathname-generation drift, non-regular inputs, CR/Unicode line separators and
control bytes fail closed. A PASS can become stale if the board changes after
the check; it does not authenticate claimed_from, grant ZERO_AUTHORITY, execute
a ticket, contact the PC/network, or authorize later bytes.

PC PULL (one button, then die — not a 10-minute watcher):
  python host/muhl_github_drive.py --go
The puller does NOT trust a prior standalone PASS. Inside the same --go run,
before its action loop, it independently freezes and revalidates its own input
snapshot: GitHub COMMANDS is pinned to one exact main commit and each listed
file is verified against its Git blob bytes; local COMMANDS freezes one name-set
and each candidate is read from a stable ordinary-file descriptor generation.
Bad/torn/oversize/malformed input, unsafe authority fields, or a local/GitHub id
collision makes the whole snapshot HOLD before dispatch. A local ticket arriving
after that run's frozen name-set is not consumed until a later run.
